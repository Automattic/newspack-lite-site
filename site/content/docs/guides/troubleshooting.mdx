title: Troubleshooting
description: Fix feeds that do not import, a feed that shows an error, and Lite Site addresses that show "Page not found".
---

Start with the problem you see. Most fixes are a setting or a single click. A few need your host or a developer, and those steps say so.

## RSS feeds are not importing on schedule

Feeds import through WP-Cron, WordPress's built-in scheduler. If nothing imports, or imports run late, work through these checks.

<Steps>
<Step>

### Look for the warning

Open the **Feeds** tab of **Lite Site > RSS**. If WP-Cron is turned off for the site, a warning says so. Imports then run only when your host sets up a separate scheduled job. Ask your host to set one up for this site.

</Step>
<Step>

### Check for an error

If the feed's **Status** shows **Error**, the schedule is running but the import fails. Go to [A feed shows an error](#a-feed-shows-an-error). If there is no error, the schedule is the problem, so continue with the next steps.

</Step>
<Step>

### Check how busy the site is

WP-Cron runs when someone visits the site. On a quiet site, imports can run later than the **Next Run** time. A visit to the site, or a job set up by your host, starts them.

</Step>
<Step>

### Check the frequency

The shortest **Frequency** is every 5 minutes. A feed set to run weekly will show **Next Run** a week away. Change it under **Edit**.

</Step>
</Steps>

<Callout title="Ask your host or developer">
If imports still do not run, ask your host or a developer to check that scheduled tasks run on this site. A developer with command-line access can run all due tasks at once with `wp cron event run --due-now`.
</Callout>

## A feed shows an error

An **Error** status means the last import failed. Hover over it, or select **Edit**, to read the message. These are the common ones.

- **A valid RSS feed URL is required.** The feed's site can no longer be found, or its address now leads to a private network. Open the feed address in a browser to check it. Use **Open Feed URL** in the drawer.
- **Couldn't reach this RSS feed.** The source did not answer, blocked your site, or returned an error. If the address opens in a browser, wait for the next run or select **Retry Now**.
- **The author set for this feed can no longer publish posts.** Select **Edit** and choose another author.

When there's no error, **Last Run** also shows the result of the import.

- **The RSS feed contains no items**. The feed loaded but has nothing to import. This is not an error on your side; it clears when the source publishes.
- **2 imported, 1 failed** or **Up to date, 1 failed**. Some items could not be saved. Any others came in or were already on the site. The next import tries the failed items again.

Two messages appear after you select **Retry Now**.

- **This RSS feed is already importing. Try again in a few minutes.** Wait a few minutes and try again.
- **Resume the RSS feed to import it.** The feed's status is **Inactive**. Set **Status** to **Active**.

For the full steps, see [RSS feeds](/docs/guides/rss-feeds/#fix-a-feed-that-shows-an-error).

## An imported entry does not show on the Lite Site

If you set **Categories** or **Tags** in [Settings](/docs/guides/settings/#choose-which-posts-appear), an entry appears only when it has one you selected. Entries come in without any. Add a category or tag to each entry, or leave these filters empty.

An entry also needs the **Published** status. See [RSS entries](/docs/guides/rss-entries/).

## A Lite Site address shows "Page not found"

Check the address first, then the settings.

<Steps>
<Step>

### Check that Lite Site is on

Go to **Lite Site > Settings** and check **Enable Lite Site** is on and saved. Until Lite Site has been turned on, its addresses show the site's "page not found" page. Once it has been on, turning it off sends readers to the main site instead: a Lite Site article opens its full version, and any other Lite Site address opens the homepage. See [Turn on Lite Site](/docs/getting-started/turn-on-lite-site/).

</Step>
<Step>

### Check the path

Compare the address with **Lite Site Path**. If you changed the path from `lite` to `text`, use `example.com/text/`. Links to the old path stop working. See [Settings](/docs/guides/settings/).

</Step>
<Step>

### Check whether the post is left out

An article shows "Page not found." when it is not published, is password protected, or is left out by your **Categories**, **Tags**, **Excluded Categories** or **Excluded Tags**. Open another published article through the Lite Site. If that works and one article does not, the post is the cause. If you just published the post, wait five minutes and try again. If the homepage opens but no articles do, refresh the address list in the next step.

</Step>
<Step>

### Refresh the address list

WordPress keeps a list of addresses. It is refreshed when you turn Lite Site on or change the path, but a plugin or your host can leave it out of date. Go to **Settings > Permalinks**. Check that a structure other than **Plain** is chosen; **Post name** is a good choice. Then select **Save Changes**, even if you changed nothing, and open the address again.

</Step>
<Step>

### Rule out another plugin

Redirect plugins can intercept Lite Site addresses. Turn them off for a moment and open the address again. If it works, add a rule to leave the Lite Site path alone, or ask a developer to.

</Step>
</Steps>

<Callout title="Site in a folder?">
If WordPress is installed in a folder, but the site address is the main domain, Lite Site addresses can be harder to set up. Ask your host or a developer.
</Callout>

## Still stuck?

Change one thing at a time and open the address again after each. If the problem remains, ask your host or a developer, and give them the address, what you see, and the steps above you tried. Developers can find more in [Developers](/docs/developers/).
